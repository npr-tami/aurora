# DirectX 11 drawing

Added. **** Code: `dll/src/vkdraw/` (`mod.rs` shared, `vulkan.rs`, `dx11.rs`).

## Which one runs
- Picked once at inject from the game exe's own import table: `vulkan-1.dll` -> Vulkan, `d3d11.dll` -> DirectX 11. Neither -> Vulkan (as before).
- Not by "is vulkan-1.dll loaded": an overlay can load it into the DX11 game. On DX11 the mod never loads `vulkan-1.dll`.
- `dll.log` says which: `draw: the game imports d3d11.dll, drawing through DirectX 11`.

## How it draws (DX11)
- A throwaway hidden window + `D3D11CreateDeviceAndSwapChain` gives the swapchain's function table: Present [8], ResizeBuffers [13], Present1 [22], ResizeBuffers1 [39]. Those dxgi.dll functions get plain inline hooks (`retour`), like the Vulkan present hook.
- Each present: take the mod's lock, then the frame (back buffer 0), check it (format, no MSAA, not 16-bit float HDR), draw, let the frame go, then the lock. Nothing of the frame is held between presents, and a resize waits on the lock, so it never meets the mod's reference.
- ESP: `ClearView` rectangles (needs Direct3D 11.1 and the driver's ClearView flag; else logged once, no ESP).
- Menu, toast, command box: one texture per slot in the frame's own format, filled with `UpdateSubresource` when the picture changes, then `CopySubresourceRegion` of each panel, clipped to the screen.
- No shaders, no pipeline state touched, nothing saved or restored.
- Formats drawn into: R8G8B8A8 and B8G8R8A8/X8 (plain and sRGB), R10G10B10A2. Others are logged once and skipped.
- `DXGI_PRESENT_TEST` presents are skipped. A present that runs inside the other one draws once.
- ResizeBuffers(1): waits for a draw in progress, then lets the game resize.
- If hooking fails, the error is kept until the next inject: no new throwaway device each time the menu opens.
- If one hook fails to go in, the ones already in come out again and are kept in memory (never freed while the game may run them).

## Hook setting and hook.txt
- "GPU driver" is Vulkan only: on DX11 the mod hooks as Auto and logs it. The Launchpad greys it out for a DX11 game.
- hook.txt: `DXGI (dxgi.dll)`, or `Steam overlay (GameOverlayRenderer64.dll)` / `Other layer (...)` when Present already jumped elsewhere before the mod hooked.

## Unload (DX11)
- Same order as Vulkan. Before taking the hooks out, each hooked function's first 16 bytes must still be ours. If another program hooked on top, the unload is refused (toast + log) and the mod stays loaded until the game closes: removing ours would crash it.

## Live test checklist (the player's DX11 Steam build)
- Inject; `dll.log` shows the DX11 pick and `dx11: hooked (...)`.
- Menu, toast, command box show and look right (colours not swapped).
- ESP boxes, labels, bones and their head rings; colours match the Vulkan ones.
- Alt-tab, resolution change, fullscreen toggle: no black screen.
- Steam overlay on and off (Shift+Tab); Ubisoft overlay.
- Unload from the menu, then inject again.
